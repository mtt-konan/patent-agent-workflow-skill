# 专利文本语体、阶段与证据表达

本参考文件用于权利要求书、说明书、摘要和内部研发稿的起草或改写。它只规范文本呈现和不确定事项的处理，不改变创造性分析、事实核验和不虚构证据的硬约束。

## 1. 先区分文本阶段

根据用户使用的“交底稿、暂行稿、草案、研发确认稿、候选申请稿、提交稿、定稿”等表述，选择相应模式。用户没有明确阶段时，默认先输出内部研发核对稿，并在开头说明当前阶段。

### 内部研发核对稿

- 保持正式专利文本的章节和语气，同时允许保留研发核对项、候选材料、待补参数、待验证机理和实验数据位置。
- 使用“发明人确认”“研发补充”“实验待验证”“资料待核”“公式待核”“内部审计”等中性标签；不使用委托关系或商业关系称谓。
- 批注要写成可回答的具体事项，例如“【研发补充】请确认微球表面官能团的种类及检测依据”，不要只写“效果不确定”。
- 批注可置于对应段落之后或单独的“研发核对项”部分。它们不属于申请文本正文，不能被误读为已经确认的技术事实。

### 申请文本候选稿

- 正文采用完整、连贯的专利语体；必要的待确认事项放在正文之外的“核对清单”，不把空白或内部对话写进权利要求。
- 尚未证实的机理可以在说明书中作为合理假设保留，但不得作为权利要求的必要限定，也不得用来替代技术效果证据。

### 提交稿

- 删除全部内部批注、候选项和空白占位符。
- 对每个待确认事项作出“确认并写入、改为可选方案、改写为推测性说明或删除”的处理；必要特征未确认时不得假装已经确认。

## 2. 专利文体的组织规则

领导式文本的专业感来自结构和逻辑闭环，不来自堆叠形容词。通常按下列链条组织：

```text
应用场景 → 现有手段及缺口 → 技术目的 → 技术方案 → 特征关系或作用解释
→ 有益效果 → 实施方式及对比例 → 测试方法和结果
```

固定句式可作为段落导航，但只有在语义条件满足时使用：

- “本发明的主要目的在于……”：提出一个与现有技术缺口对应的主要技术目的，内容对评述第三节，不要写成「提供一种……使……」；两类技术问题见 `examination-guidelines.md`；
- “本发明的另一目的在于……”或“同时，本发明还公开……”：确实存在第二个有保护价值且有说明书支撑的对象时使用；
- “为实现上述目的，本发明提供如下技术方案……”：后文紧接具体组成、结构、步骤或关系，不用来引出愿望性效果；
- “在一些实施方式中……”：引出可选特征或替代方案；
- “进一步地……”：引出有层次的从属限定或实施例细化；
- “以下结合实施例……”：转入可重复的原料、步骤、条件和测试方法；
- “本发明至少具有如下有益效果之一……”：只列有技术依据的效果，并按证据强度选择措辞。

权利要求和说明书中应保持术语、缩写、单位、对象名称和逻辑关系一致。自定义词、特殊含义及存在多种口径的限定词或参数，应在说明书适当位置给出明确的定义、说明或测定口径；通常含义清楚的本领域术语不要求逐一定义。登记、定义位置和引用基础按 `terminology-and-consistency-workflow.md` 核对。注意“包括”“基本由”和“由……组成”的开放程度不同，不得为追求语气而混用。

## 3. 积极但分级的表达

默认使用正式、积极、技术中性的语气，避免在申请文本正文中出现道歉式或自我否定式说明，例如“目前没有实验结果，暂不能得出结论”。这类信息应转入研发核对项；正文按照实际证据选择下列表达强度：

- 已由交底、原料资料或实验记录确认：可使用“包括”“采用”“为”“形成”“测得”“测试表明”；
- 由技术关系可以合理预期，但尚无完整对照：可使用“有利于”“可促进”“能够调节”“具有……趋势”“有助于”；
- 机理尚属解释性假设：可使用“在不受具体理论约束的情况下，本发明的作用机理可解释为……”“一种可能的作用机理是……”“其效果可能与……有关”；
- 只有在同一测试方法下有可靠对照时，才使用“显著”“明显”“极佳”“协同”“远优于”“突破技术偏见”等强结论。

“可能”“推测”是对机理或原因的限定，不是对事实和数据的免责。机理推测必须具有技术合理性、与实施方式一致，并且不能单独承担充分公开、创造性或性能结论。

积极表达优先使用有技术含义的动词，如“构建、调控、促进、增强、稳定、赋予、改善、降低、便于”，而不是无证据的宣传性形容词。若效果尚未测定，可写成技术目的或预期作用；不得把预期作用改写成“已经实现”的结果。

## 4. 研发批注与待确认事项

每一项批注应说明“缺什么、由谁提供哪类技术信息、补上后影响哪一段”。推荐使用以下标签：

- `【发明人确认】`：材料组成、必要技术特征、方案版本或用途是否确实如此；
- `【研发补充】`：原料型号、供应商、固含量、官能团、工艺条件等可复现实验信息；
- `【实验待验证】`：键合、迁移、粒子分布、协同、耐久性或性能差异；
- `【资料待核】`：全文段落、公开日期、单位、术语或来源；
- `【公式待核】`：公式本体、变量、密度类型、粒径口径和单位；
- `【内部审计】`：权利要求、说明书、实验设计之间的支撑或一致性问题。

必要技术特征未确认时，应在核对区提出明确问题，不得用空白、随意型号或猜测性数值填满权利要求。可选特征可以先作为候选从属方案，但要标明其依据和待确认状态。正式稿中应逐项处理这些标记，不能遗留“请补充”或括号空白。

## 5. 效果、机理和实验的对应

起草有益效果或机理段落前，先建立以下对应关系：

```text
技术特征 → 可能的作用 → 可观测指标 → 对照组或资料依据 → 允许的表述强度
```

例如，工艺中省去预制复合微球的步骤，可以直接表述工艺路径的差别；表面粗糙度、接触角和滚动角可以支持相应的测试结果；没有形貌或化学键证据时，不把 Rq 或接触角单独写成已经证明了微纳结构、迁移富集或化学键合。对比例不足时，效果写成“有利于”或“可用于考察”，不要写成“显著优于”。

## 6. 起草完成后的文本审计

复核范围和检查去重以 `terminology-and-consistency-workflow.md` 第 5 节为准；支持、术语、引用和参数核对并入同一轮。本模块只补充适用的语体和阶段检查：

- 固定句式与实际保护对象、段落功能相符，不因模板预填而增加无依据的目的或效果。
- 效果及机理用语与证据状态相符，预期不写成已实现。
- 内部研发稿的批注明确、可回答，并与正文区分。
- 候选稿或提交稿正文不残留空白、内部对话、委托关系称谓或未经核实的结论。
