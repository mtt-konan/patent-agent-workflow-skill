# 案件 Markdown 版本管理

进入案件且本轮会写或改 Markdown 时执行。用户只要解释或审查、且未改文件时，不要 `git init`，也不要提交。

## 仓库

先确认当前案件目录，并检查已有仓库根目录、工作区和暂存区状态。在**当前案件目录**实行一案一库，不在工作区根目录建总库。已有本案仓库就复用；若仅被父目录仓库覆盖，不自动嵌套建库或改动父库，完成正文后报告版本管理边界待定。

尚未建库时：

```powershell
git init
```

若没有 `.gitignore`，写入：

```
*
!*/
!*.md
!.gitignore
tmp/
*-暂行稿.md
```

已有 `.gitignore` 则先读，不要覆盖用户已有规则。除本轮建库所需的 `.gitignore` 外，不把非 Markdown 文件加入暂存。

## 跟踪什么

只跟踪案件正文和工作底稿的 `.md`。`workbench/` 下的状态和支撑清单要入库。案件根目录 `实验设计.md` 入库。

不入库：交底原文、对比文件、xlsx 实验表、PDF、DOCX、XLSX、PPTX、图片，以及 `tmp/` 里的提取物（即使是 `.md`）。

## 文件名

正文用稳定文件名，放在案件目录根下：

- `创造性检索分析.md`
- `权利要求书.md`
- `实验设计.md`
- `说明书.md`
- `摘要.md`

方案版本写在文内和 `workbench/00_案件状态.md`。同一方案的文本迭代用 git 提交，不要另存 `权利要求书-V1.md`、`说明书-暂行稿.md` 一类并列文件。实质技术方案变化时仍按 `V1`/`V2` 在文内换版，不靠文件名后缀做历史。

新建正文使用稳定文件名；局部修改沿用用户指定的现有文件，不因版本后缀自动重命名。只有本轮包含文件整理、迁移或已授权重命名时，才核对当前采用稿、引用关系和目标路径后归并。目标文件已存在时先比较，不能直接覆盖、合并或删除；不能确定采用关系时保留双方并报告冲突。旧稿默认保留；删除须有明确授权，已有跟踪文件也不自动移出版本管理。

## 提交

本轮改了入库的 Markdown 后，在能独立提交本轮变更时提交一次，说明改了哪些正文；没有变更则不提交。

- 先与开始时的工作区、暂存区状态比较，只暂存明确属于本轮的文件或补丁；不用 `git add .`、`git add -A` 或 `git commit -a`。
- 开始时已有暂存内容，默认保留原索引并暂缓本轮提交，除非用户已明确授权一并处理。目标文件已有用户未提交修改时，只有能可靠分离本轮补丁才提交；否则保留修改并报告未提交原因，不替用户暂存、回退、清空或 stash。
- 提交前核对暂存差异与文件清单；身份未配置或提交检查失败时保留正文，报告原因，不修改全局 Git 身份或绕过检查。
- 未能安全提交不影响完成正文和复核。不要 `git push`（除非用户明确要求），不要改历史。
