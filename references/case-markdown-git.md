# 案件 Markdown 版本管理

进入案件且本轮会写或改 Markdown 时执行。用户只要解释或审查、且未改文件时，不要 `git init`，也不要提交。

## 仓库

在**当前案件目录**初始化，一案一库。不要在工作区根目录建总库，以免多案历史混在一起。该目录已是 git 仓库则不要再 `git init`。

尚未建库时：

```powershell
git init
```

若没有 `.gitignore`，写入：

```
*
!*/
!*.md
!.gitignore
tmp/
*-暂行稿.md
```

已有 `.gitignore` 则先读，不要覆盖用户已有规则；本轮仍不得把非 Markdown 加入暂存。

## 跟踪什么

只跟踪案件正文和工作底稿的 `.md`。`workbench/` 下的状态和支撑清单要入库。案件根目录 `实验设计.md` 入库。

不入库：交底原文、对比文件、xlsx 实验表、PDF、DOCX、XLSX、PPTX、图片，以及 `tmp/` 里的提取物（即使是 `.md`）。

## 文件名

正文用稳定文件名，放在案件目录根下：

- `创造性检索分析.md`
- `权利要求书.md`
- `实验设计.md`
- `说明书.md`
- `摘要.md`

方案版本写在文内和 `workbench/00_案件状态.md`。同一方案的文本迭代用 git 提交，不要另存 `权利要求书-V1.md`、`说明书-暂行稿.md` 一类并列文件。实质技术方案变化时仍按 `V1`/`V2` 在文内换版，不靠文件名后缀做历史。

磁盘上若已有 `*-V1.md` 且就是当前采用稿，先收成上列稳定文件名再入库。已被取代的 `*-暂行稿.md` 留在磁盘即可，不入库、不再改。

## 提交

本轮改了入库的 Markdown 之后提交一次，说明改了哪些正文。没有变更则不提交。不要 `git add` 非 md，不要 `git push`（除非用户明确要求），不要改历史。
