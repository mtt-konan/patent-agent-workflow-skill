# 术语管理与一致性审计

用于申请前权要、说明书的起草、修改和一致性检查；评述、实验设计改动共用术语、参数或组编号时，检查受影响的对应关系。只审查时不改文件，也不因一致性检查重跑检索。本模块不依赖专用校对软件；尚未通过实案试点，不宣称自动保证全文一致或达到提交标准。

## 1. 确定范围和依据

按任务确认当前案件、文本阶段及读写范围。实质审查或跨文件核对时复用已有 `workbench/00_案件状态.md` 与相关底稿；局部文字、编号修改不要求重读整案或新建术语档案。不要为了补齐流程创建空文件。只审查时术语整理和发现均在对话交付，不写回底稿。

条文按 `examination-guidelines.md` 定位原 PDF，不把软件规则或内部偏好当成法规。与本模块直接相关的条文是第二部分第二章 2.2.7（术语、符号与自定义词，2023 版印刷页 152-153）、3.2.1（支持）、3.2.2（清楚）、3.3（权要与说明书术语一致，印刷页 162）、3.3.2（从属引用，印刷页 165-166）。适用时核对版本及相关后续修订，按条文的条件和例外判断。

## 2. 复用案件术语记录

起草前从交底和当前权要提取需要持续保持一致的对象、步骤、材料、参数、缩写和附图标记。优先维护 `workbench/01_交底事实与术语.md` 中的条目；已有等价记录则沿用。只登记影响本案理解或保护范围的用语，不建覆盖全文普通词汇的字典。用 Markdown 条目，不用表格。

每个条目写清以下适用信息，不相关的字段可省略：

- 规范名及所指概念；名称相近的不同对象要分别记录。条目较多时可用稳定编号辅助定位，编号不进入专利正文。
- 交底原称、允许的简称或缩写、确定不应混用的别名；尚不确定是否同义的表达单列为待核，不能直接放入禁用清单。
- 上位概念、下位实例、组成或功能关系；不要把这些关系登记为同义替换。
- 通常含义是否足够清楚；若需定义或测定口径，记录拟用表述及其依据、说明书中的位置。未写入正文的定义不能记为已经公开。
- 事实出处和当前使用位置，以文件及章节、段落或行号定位；资料缺口保留证据状态，不为补齐字段编造定义。

能根据现有材料确定的名称直接登记。只有存在会影响技术含义、保护范围或事实基础的歧义时，提出具体待确认项；不要求用户逐词批准。查新检索使用的同义扩展词属于检索要素，不自动成为申请文本的可换用术语。

## 3. 起草和定义

同一概念在对应位置沿用规范名。发明内容按当前权要的特征和关系展开；实施方式使用下位实例时，明确其与上位概念的关系，不能用“即”把优选实例无意写成唯一含义。固定名称不等于把合理的上位范围收窄为单一材料、结构或实施例。

按以下边界处理定义和首次使用：

- 通常含义清楚的本领域术语可直接使用，不要求每个专业词都先写定义。
- 自定义词、特殊含义及多种测定口径会影响范围的参数，应有明确的说明或可操作口径。作为内部撰写约定，优先在说明书首次实质使用处或此前解释；不把这一位置偏好表述成所有专业词的法定前置要求。
- 权要中的用词应尽可能从自身表述即可明确含义。说明书中的定义不能替代权要内部缺失的指代基础。
- 非中文技术名词首次使用、简称、变量、单位和附图标记分别核对；已明确绑定的全称与简称可以并存。
- 新出现的专业表达先与术语记录比对，判断是原概念、下位实例还是新对象，再采用对应名称；不得为了消除告警随意扩大定义或合并不同对象。

## 4. 分别做词面检查和语义复核

检查结果分为“确认问题”“待核疑点”和“已核对的例外”。每项发现应能回到实际原文。可用全文搜索、`rg` 或任务内的小脚本辅助定位，但未覆盖的表达不能据此认定一致。

### 词面和结构

- 查已登记的别名、名称拼写、缩写、变量、单位及编号；排除引用文献原名、背景中的他物、已说明的简称等适用例外。
- 核对需要定义的术语是否在说明书中实际解释，记录定义和使用位置；定义只存在于底稿或外部文献时标记缺口。
- 从当前权利要求建立直接引用和间接引用关系，检查缺号、引用在后项、多项从属引用及主题名称；涉及“所述”等指代时按实际引用链核对。
- 核对同一方案、实施组和测定口径下的参数、单位、公式变量、图号和组编号；不同实施例的合法取值变化、不同参数的相似名称不应被合并成冲突。

### 语义和支撑

- 通读关键段落，寻找词表外的近义表达和同名异义；列出两处原文及判断理由，不能只给“存在术语不一致”的笼统结论。
- 判断部件关系、步骤先后、必要与可选、数值范围及定义外延是否改变。字面统一后仍可能存在技术关系矛盾。
- 对每个权要限定，核对说明书中的技术关系、范围和实施依据。词语出现或相似度高，只能证明找到候选段落；不能直接证明支持或充分公开。未逐项核对的支撑事项应说明检查边界。

引用基础尤其要注意作用范围：当前项可以使用本项此前引入及其有效引用链继承的对象，不能从未引用的相邻项借用；多个独权的对象不自动共享。多项择一引用要分别核对每条分支，不能把各分支的特征取并集当作共同基础。若权5仅引用权1，而某对象仅在权2中引入，“全文此前出现过”不足以说明权5中的“所述对象”具有引用基础。

## 5. 定位、修正和复核

沿用 `workbench/06_文本逻辑审计.md` 或已有审计区，以条目记录：问题类别和状态、相关文件位置与短引文、规则来源或内部约定、影响及建议处理。简单检查可直接在对话交付；不为没有发现的问题生成空报告。

用户授权修改时，按依据局部修正。规范名、定义或参数口径变化后，同步更新术语记录并搜索全部受影响位置，再核对对应关系；避免为处理个别问题通篇润色。若关联文件不在本轮修改范围，只报告位置和影响。修改记录不能替代对最终文本的重新读取。

本节统一管理复核范围。完整起草或全面审查覆盖本轮请求的全文及必要关联；局部修改只核对改动和受影响链条：文字更名检查对应引用位置，权项编号变化核对直接及间接引用，定义或特征关系变化复核支持与保护范围，组编号或配方变化核对实验设计和具体实施方式。权要、语体等模块的适用项目并入这一轮检查，已通过的项目仅在新改动、新证据或失败影响它时重查。

仍缺事实或存在多种合理解释时，保留具体待核项，不靠反复改写生成确定结论。关联文件是否可改遵循 `SKILL.md`，检查不扩大授权范围。

交付说明检查了哪些文件、解决了什么、尚待确认什么，以及没有覆盖的对象或图像。只有实际运行过的检查才能写“已检查”；不以总体评分或模型自评代替证据。

## 6. 小规模试点

用户指定试点后，在单一案件的约定范围内验证本模块，不自动扩展到其他案件。先记录原稿发现，再在授权范围内修正和复核。

需要测量检出能力时，可在该案 `tmp` 使用复制稿或合成短例，加入已知的别名、定义遗漏、错引、参数口径冲突等错误，同时保留允许简称、上位与下位关系、多实施例取值等正确例。记录漏报、误报、修改引入的新问题和复核工作量；测试错误不写回案件正文。依据试点结果补规则，不把一个案件的材料命名习惯推广为通用禁词。

## 7. 代理文本一致性模式

用户只要求检查交底书、权利要求或说明书的逻辑和前后一致性时，进入本模式，不自动扩展到创造性检索、技术可行性判断或生物/化学事实核验。可以使用交底书、待审文本及用户明确指定的关联文件；不要求 PatentLint、Vale 或其他专用工具。工具只作为词面、格式、编号和重复扫描的辅助，不能替代上下文语义判断。

先按同一版本建立对照范围，再分别检查：术语和缩写、权项引用链、技术对象和产品阶段、步骤顺序、参数/单位/测试口径、实施例与对比例编号、数据与样品归属、目的-方案-效果衔接、内部批注和占位符。交付结果分为“原问题已解决”“部分解决”“仍存在”“修改稿新增”，每项保留文件位置、短引文、影响和建议；不把外部技术常识推断写成对技术事实的否定。

如果修改稿含有“请补充”“或保留”“现有内容不变”等内部讨论，应按文本阶段标记：内部核对稿可保留，但必须与申请正文区分；候选稿和提交稿应移出正文或逐项处理。比较交底与修改稿时保留原问题编号，避免只给孤立评分。案件审查中发现的通用流程问题，先列为技能改进建议；用户要求维护技能时再修改，不为单案材料新增普遍禁词。
