# 说明书起草

由 `SKILL.md` 进入说明书节点后再读本文件。写之前先读本案 `创造性检索分析.md` 和 `权利要求书.md`。已有锁定的 `实验设计.md` 时再读它，具体实施方式的组编号和中心组配方跟它；未锁定时不要把组数写死。用户只要解释时，默认不改文件。不虚构测定结果。

骨架固定为：发明名称，技术领域，背景技术，发明内容，具体实施方式。有图才写附图说明。缺的章节直接不写，不留空表，不写待填，不另建研发填写接口。

除实验设计外，说明书不用 Markdown 表格。给技术人员的说明写进具体实施方式，用说明书口气写清组怎么设、中心配方怎么做、其他组改哪一项、测什么、怎么测，不要写成当面叮嘱或权要编号对照。

## 发明名称

与权利要求书的发明名称一致。方案版本、是否提交稿等内部说明写 `workbench`，不写进说明书正文。

## 技术领域

写所属领域和保护对象。交底有技术领域则照搬或略改。

## 背景技术

1. 交底有背景技术或同等叙述：默认把甲方已写好的应用场景、现有手段和不足搬进来，保留能读懂的长度。需要改动后再搬入的，限于与已核对比文件明显不符、把未测性能写成领域已解决或本发明已实现、篇幅明显不适、术语与其余文本不一致。
2. 交底没有背景技术：自行撰写，写到审查员能看懂用在什么场合、现有手段是什么、卡在哪。
3. 已评述并拟在申请中面对的对比文件写入背景，每件一两句说明公开了什么、仍留下什么缺口。不要写「未给出结合启示」一类审查用语。
4. 背景最后的技术问题用创造性检索分析第三节原句。第三节必须是对比文件留下的路径缺口，不能是对比文件已经解决的技术目的。若评述第三节仍写成现有技术已能做到的事，先改评述再写入说明书，不要照抄错句。不得把本案配方逐步写进问题句。

## 发明内容

按当前权利要求展开，作为权要支撑。先写独权，从属用「进一步地」。交底里有组分作用、且不是未证键型或协同的，可以写功能。

发明内容最后写有益效果，口径取创造性检索分析第二节。有对照结论的，用对照后已经成立的效果。没有对照的，只写相对最接近文件的路径或工艺差别，不写待证性能，不把权利要求方案复述成效果。

## 具体实施方式

顺序：套话，各组设置和验证目的，中心实施例的完整过程，其余组只写相对中心改了什么，原料、设备与表征方法。有锁定实验时这些都写进这一节。不要另建填写接口。

套话用常规两句：实施例仅帮助理解；未注明的步骤按常规或文献，未注明厂商的原料和仪器可市购。不要写供应商专节，不要为供应商留空。

中心实施例写可重复的完整制备。其他实施例和对比例只写相对中心改变的因素和用量。分组和对照关系以 `实验设计.md` 为准；xlsx 只给研发填数。说明书正文用文字写清各组验证目的，不要把实验设计的成对对照句原样搬进来。

无测定时，实验结果只列需测项目和测试条件，不写空表、不编数字。数据回来后再写入读数和分析，并重组织有益效果。
